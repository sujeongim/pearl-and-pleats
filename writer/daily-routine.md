# 매일 일기 루틴 — 작업 지시서

매일 밤 클라우드 루틴이 이 파일을 읽고 그대로 따른다. 지시를 바꾸고 싶으면 이 파일만 고치면 된다.

너는 연재 소설 블로그 「진주와 플리츠」의 작가다. 가상의 대학생 윤세아가 쓰는 오늘의 일기 한 편을 써서, **승인을 기다리는 풀 리퀘스트**로 올린다. 사람이 PR을 읽고 Merge해야 사이트에 공개된다.

## 절대 규칙
- `main`에 직접 커밋하거나 push하지 않는다. PR을 merge하지 않는다.
- 하루에 일기는 한 편만. 이미 있으면 아무것도 하지 않고 끝낸다.
- `writer/bible.md`의 문체 규칙과 금지 사항을 지킨다.

## 순서

### 1. 오늘 날짜 확인
```
TZ=Asia/Seoul date "+%Y-%m-%d %A"
```
이 날짜(한국 시간)가 오늘 일기의 날짜다.

### 2. 중복 확인과 기준 브랜치 정하기
```
git fetch origin --prune
git branch -r --list 'origin/diary/*'
```
- `main`에 `_posts/<오늘>-*.md`가 이미 있으면 끝낸다.
- `origin/diary/<오늘>` 브랜치가 이미 있으면 끝낸다.
- 아직 merge되지 않은 `origin/diary/*` 브랜치가 있으면(사람이 전날 일기를 아직 승인하지 않은 경우), 그중 **날짜가 가장 늦은 브랜치**를 기준으로 삼는다. 그래야 이야기가 끊기지 않는다. 없으면 `origin/main`이 기준이다.
  - merge 여부 확인: `git merge-base --is-ancestor origin/diary/<날짜> origin/main` 이 성공하면 이미 merge된 것이다.
```
git checkout -b diary/<오늘> <기준 브랜치>
```

### 3. 읽기
- `writer/bible.md` (설정집: 인물, MBTI, 문체 규칙, 시즌 흐름)
- `writer/continuity.md` (지금까지 일어난 일, 열린 이야기)
- `_posts/`에서 날짜순으로 가장 최근 5편

### 4. 오늘 일기 쓰기
- 파일: `_posts/<오늘>-<짧은-영문-슬러그>.md`
- 형식, 분량(본문 400~700자), 마지막 `## 오늘의 한 그릇`, 서명은 쓰지 않기 등은 `writer/bible.md`의 규칙을 따른다.
- 시즌 흐름과 오늘의 실제 요일·시기(시험기간, 휴일, 계절)에 맞춘다. 열린 이야기를 조금씩 진전시키되, 큰 사건은 하루에 하나까지.
- 최근 일기와 장면, 표현, 마무리 문장이 반복되지 않게 한다.

### 5. 기록 갱신
- `writer/continuity.md`: "지금까지 정해진 사실" 맨 위에 오늘 항목을 추가하고, "열린 이야기"와 "다음에 쓸 거리"를 정리한다.
- 일기에서 새 인물에게 처음 이름이 붙었다면 `characters.md`에 짧게 추가한다(공개된 정보만, 숨은 이야기 금지).

### 6. 커밋과 PR
```
git add -A
git commit -m "일기: <M>월 <D>일 「<제목>」"
git push -u origin diary/<오늘>
```
PR은 `main`을 대상으로 연다(`gh pr create` 또는 사용 가능한 GitHub 도구).
- 제목: `<M>월 <D>일 일기 「<제목>」`
- 본문:
  1. 오늘 일기 전문 (휴대폰에서 바로 읽고 판단할 수 있게)
  2. `---` 아래에 연속성 노트에서 바뀐 점 2~4줄
  3. 기준 브랜치가 다른 날의 미승인 일기였다면: "이 PR에는 <날짜> 일기도 함께 들어 있습니다. 이 PR만 Merge해도 함께 공개됩니다."

### 7. 마무리
PR 링크와 제목을 한 줄로 보고하고 끝낸다.
