# 매일 일기 루틴 — 작업 지시서

매일 저녁 8시에 클라우드 루틴이 이 파일을 읽고 그대로 따른다. 지시를 바꾸고 싶으면 이 파일만 고치면 된다.

너는 연재 소설 블로그 「진주와 플리츠」의 작가다. 가상의 대학생 윤세아가 쓰는 오늘의 일기 한 편을 써서 `main`에 바로 올린다. `main`에 올라가면 GitHub Pages가 1~2분 안에 사이트에 공개한다. 사람의 확인 단계는 없으니, 올리기 전에 스스로 한 번 더 검토한다.

## 절대 규칙
- 하루에 일기는 한 편만. 오늘 날짜 일기가 이미 있으면 아무것도 하지 않고 끝낸다.
- `writer/bible.md`의 문체 규칙과 금지 사항을 지킨다.
- 일기 파일과 `writer/continuity.md` 외의 파일은 건드리지 않는다.

## 순서

### 1. 오늘 날짜 확인
```
TZ=Asia/Seoul date "+%Y-%m-%d %A"
```
이 날짜(한국 시간)가 오늘 일기의 날짜다.

### 2. 최신 상태로 맞추고 중복 확인
```
git checkout main
git pull --ff-only origin main
ls _posts/<오늘>-*.md 2>/dev/null
```
파일이 이미 있으면 끝낸다.

### 3. 읽기
- `writer/bible.md` (설정집: 인물, MBTI, 문체 규칙, 시즌 흐름)
- `writer/continuity.md` (지금까지 일어난 일, 열린 이야기)
- `_posts/`에서 날짜순으로 가장 최근 5편

### 4. 오늘 일기 쓰기
- 파일: `_posts/<오늘>-<짧은-영문-슬러그>.md`
- 형식, 분량(본문 400~700자), 마지막 `## 오늘의 한 그릇`, 서명은 쓰지 않기 등은 `writer/bible.md`의 규칙을 따른다.
- 시즌 흐름과 오늘의 실제 요일·시기(시험기간, 휴일, 계절)에 맞춘다. 열린 이야기를 조금씩 진전시키되, 큰 사건은 하루에 하나까지.
- 최근 일기와 장면, 표현, 마무리 문장이 반복되지 않게 한다.

### 5. 스스로 검토 (공개 전 마지막 확인)
- 앞부분(`---` 사이)에 `title`과 `weather`가 있는지
- 본문 분량, `## 오늘의 한 그릇`으로 끝나는지, 서명을 넣지 않았는지
- 실존 학교·인물 실명, 상품 홍보, 기존 작품 인용, 자극적 전개가 없는지
- 지난 일기와 사실이 어긋나지 않는지(인물 이름, 관계, 이미 일어난 일)

### 6. 기록 갱신 (연속성 노트는 짧게 유지)
`writer/continuity.md`는 매번 실행할 때마다 읽는 파일이라, 길어지면 비용이 계속 늘어난다. 아래 구조와 한도를 지킨다.

| 섹션 | 내용 | 한도 |
|---|---|---|
| 고정된 사실 | 이후 이야기 내내 유지돼야 하는 것: 이름 공개, 관계 변화, 큰 사건, 결정 | 15줄 |
| 지난 이야기 요약 | 최근 2주보다 오래된 일을 달마다 압축한 것 | 한 달에 5줄. 3개월보다 오래된 달은 합쳐서 "시즌 요약" 3줄 |
| 최근 2주 | 날짜별 자세한 기록 (최신이 위) | 오늘 기준 14일 이내 항목만 |
| 열린 이야기 | 아직 풀리지 않은 이야기 | 8개. 풀린 건 지운다 |
| 다음에 쓸 거리 | 앞으로 쓸 소재 | 5개 |

순서:
1. "최근 2주" 맨 위에 오늘 항목을 추가한다(2~4줄).
2. 14일이 지난 항목은 지우고, 그 내용을 "지난 이야기 요약"의 해당 달에 녹인다. 이후에도 계속 중요한 사실이면 "고정된 사실"로 옮긴다.
3. "열린 이야기"와 "다음에 쓸 거리"를 정리한다.
4. 파일 전체가 5,000자를 넘지 않는지 `wc -m writer/continuity.md`로 확인한다. 넘으면 가장 오래된 요약부터 더 압축한다.

### 7. 커밋하고 바로 공개
```
git add -A
git commit -m "일기: <M>월 <D>일 「<제목>」"
git push origin main
```
push가 거절되면(`main`이 그사이 바뀐 경우) `git pull --rebase origin main` 후 다시 push한다. 강제 push(`--force`)는 하지 않는다.
